# 油品价格维护（可恢复多端台账）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 端到端自检：`npm run verify`（模拟多终端、旧数据迁移与写入崩溃恢复）

数据仍保存在浏览器 `localStorage` 中，但写入模型从「直接覆写」升级为带预写日志（WAL）的多端台账。
用多个浏览器标签页打开即可模拟两台值班终端同时操作；各端通过 `storage` 事件与版本号轮询实时同步挂牌板。

## 业务规则

- **同一油品只接受一个待生效版本**：已有待生效调价单时，后到终端的新单不会覆盖，先留存为「冲突草稿」并排队。
- **生效后重算差额**：前序版本生效、挂牌价刷新后，队首冲突草稿按新挂牌价重新计算基准价与差额，自动升级为待生效；其余草稿继续排队。
- **列表 / 汇总 / 待处理提示**统一以「最新生效价挂牌板」为唯一价格来源。
- **回退**：已生效单回退后挂牌价恢复到上一生效价，待生效单回退后队首草稿递补，备注中追加回退原因。
- **旧数据迁移**：首次打开新台账时自动迁移 `dfwlfront-9-price` 旧记录；原记录、状态（生效中 / 待确认 / 已回退）与备注完整保留，迁移单带「旧」标记并保存原始字段。同油品多条旧「待确认」自动整理为一张待生效 + 冲突草稿队列。

## 可恢复性

- 每次调价是一个事务：先写 WAL（`dfwlfront-9-ledger-wal-v1`）→ 纯函数推演 → 缓存结果 → 一次性写主台账（`dfwlfront-9-ledger-v1`）→ 清 WAL。
- **操作日志与价格快照同事务写入**：每条日志都带事务提交时刻四种油品的完整挂牌价快照。
- 写到一半关闭页面 / 配额异常 / 其它终端崩溃：WAL 超过失活阈值后由下次操作或开机流程接管，`intents` 阶段按原意图补提交、`applied` 阶段直接落缓存结果，并追加 `recover` 日志。
- 多端写入靠 WAL 槽互斥：占用中时自动退避重试，不再出现后提交盖掉先写入版本的情况。

## 目录

- `src/ledger/types.ts` —— 台账、调价单、日志、WAL 类型
- `src/ledger/engine.ts` —— 纯函数业务引擎（迁移、冲突、生效重算、回退）
- `src/ledger/storage.ts` —— WAL 两阶段提交、崩溃恢复、多端互斥、开机引导
- `src/stores/priceStore.ts` —— Pinia store（视图派生、跨标签同步、提示）
- `scripts/verify.ts` —— 端到端自检脚本
