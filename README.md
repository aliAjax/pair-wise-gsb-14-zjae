# 油品价格维护 · 多端可恢复调价台账

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 端到端测试：`npm test`（55 项断言：多端冲突、故障恢复、旧账迁移、回退、队列递补）

## 解决的问题

原实现把记录直接覆盖写入单份 localStorage，两个值班终端同时保存时后提交会覆盖先到版本，
写到一半关闭页面还会留下半份记录。现已改造为**多端可恢复台账**。

## 台账模型（`src/types.ts` / `src/engine.ts`）

- **一个油品一个待生效槽位**：提交在 Web Lock 内锁内重读磁盘最新台账判定。
  槽位空闲 → 调价单列为「待生效」；已被占用 → 后到终端的单据留为**冲突草稿**（记录阻塞来源），绝不覆盖先到版本。
- **生效后自动重算递补**：待生效版本生效时，价格快照与操作日志在同一持久化屏障写入；
  队首冲突草稿保留原报价、按新挂牌价重新计算差额（`diff = 草稿价 - 最新生效价`）并自动递补为待生效，
  其余草稿把阻塞关系转挂到新单据，形成排队链。
- **可恢复写入（预写事务 + 屏障落盘）**：
  1. 先把事务头（含完整操作计划 `ops`）落盘；
  2. 每步操作（调价单 / 快照+日志 / 队列转挂）执行后立即落盘并推进 `appliedOps`；
  3. 全部完成后摘除事务头（提交点）。

  任意一步异常或中途关闭页面，重开页面（或任意在线终端）发现事务头即自动从断点重放；
  每个 op 都有幂等守卫，日志/快照不会重复写入，不会留下半份记录。
- **旧数据迁移**：首次打开若存在旧键 `dfwlfront-9-price`，一次性迁入新台账
  （`src/engine.ts` 的 `migrate`）：原有记录、原始状态（保存在 `legacyStatus` 并在详情中展示）、
  备注全部保留；旧 JSON 写到一半损坏时按对象边界抢救完整记录。旧键保留作为备份。
- **统一口径**：油品看板、平均挂牌价、每张单的差额、待处理提示都只跟**最新一张已生效价格快照**走，
  待生效价、草稿价不计入汇总。

## 多终端联调

多开浏览器标签页即代表多台值班终端（终端 ID 存于 sessionStorage，可用顶部按钮切换）。
跨页写入通过 Web Locks API 串行化，通过 `storage` 事件互相同步；
任一终端发现别的终端有未完成事务时可代为恢复。

## 故障演练

调价表单下方提供「写入异常演练」：开启后下一次写入按步骤落盘（每步 0.7 秒），
可在中途刷新/关闭页面；也可在指定步骤直接抛出存储异常（一次性触发）。
恢复后操作日志会出现「故障恢复」记录，可在「操作日志」页核对全过程。

## 目录

- `src/types.ts` — 台账/事务/快照/日志数据模型
- `src/storage.ts` — localStorage 适配、跨终端锁与同步、损坏 JSON 抢救
- `src/engine.ts` — 迁移、事务构建与幂等重放、冲突排队、生效级联、回退
- `src/store.ts` — Pinia 视图模型（看板、汇总、待处理均派生自最新生效价）
- `src/App.vue` — 台账看板 / 调价明细 / 价格快照 / 操作日志四个视图
- `test/scenario.ts` — 端到端场景断言（内存存储 + esbuild 打包运行）
